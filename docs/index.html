Run the official Claude Code CLI on any model

Independent project, not affiliated with or endorsed by Anthropic.

Paste an API key from NVIDIA NIM, OpenRouter, OpenAI, Gemini, Groq, DeepSeek, Kimi, GLM, xAI, Mistral, Anthropic, a local Ollama, or any compatible URL. Pulsar Code recognises the provider, lets you pick a model and starts Claude Code, unmodified, with your project's skills, hooks and MCP servers still working.

  • 36 providers in v3.0.0
  • router on 127.0.0.1, token-gated
  • no telemetry
  • macOS · Linux · WSL · Windows

From the first public release, pin a checksum-checked release instead: set PULSAR_REF=v3.0.0 and fetch the installer from the same tag. Release archives are checked against the release's SHA256SUMS before anything is unpacked; releases published while the repository is public also carry build provenance you can check with gh attestation verify. Pulsar Code's Python dependencies come from PyPI.

Uplink · runs in your browser

The beam finds your provider

Pulsar Code recognises a key by its shape, offline, longest prefix first. This page carries the same prefix table as the CLI: type a prefix or pick one, and the beam swings to the profile it belongs to.

Drag to pan

36 providers in v3.0.0 on four orbits around Pulsar Core, grouped by how Core reaches each profile: local 6, native 6, cloud 2, keyed adapters 22. The beam turns at the speed of the terminal's own boot beam.

Signal path · relay before the first byte

One reply, one model, a plan B

Claude Code talks to Pulsar Core on 127.0.0.1 with a session token. Core holds the line with SSE pings while it opens the provider, and commits to the first target that answers.

Drag to pan

Before the first 200, any target may fail and the next in the session plan takes over. After it, Pulsar Core streams only from that target.

  1. You paste a key; its prefix names the provider, longest prefix first. Bare sk- keys ask you to choose.
  2. Claude Code sends Anthropic Messages to Pulsar Core with a local session token. Core picks one wire per model: native, chat completions or the Responses API.
  3. A 429, 5xx, timeout or rejected key before the first byte moves the same request to the next target. After the commit, a failure ends the reply with a readable notice.

Hot swap

/pulsar:switch <model> inside the session, pulsarcode switch <model> from another terminal, or Claude Code's own /model. It takes effect on the next message.

Translation for open models

Fresh tool ids, tool calls emitted as text are rescued, long tool names get a stable alias, and a tool call cut off mid-arguments is withheld instead of run.

Self-healing requests

A rejected parameter is adjusted and retried, and the fix is remembered per model for a week.

Real context windows

Claude Code compacts inside the model's real window, up to its 1M mode (windows between 200k and 1M are used as 200k), and overflow errors come back as "prompt is too long", so compaction engages.

Loop guard

Four identical steps in a row are answered with an explanation instead of another provider call (PULSAR_LOOPGUARD=0 turns it off).

Cloud routes

Amazon Bedrock and Google Vertex AI take a different route: Claude Code talks to the cloud directly with its own auth.

Extras · through Claude Code's plugin and hooks interfaces

More than a launcher

Claude Code gains a few new senses: the model can present, ask a second opinion, see the screen when you allow it, and you can watch the traffic.

Stage

The model presents decks, charts, diagrams, code, tables, metrics, timelines and progress. Inside Claude Code as a live pane on Claude Code 2.1.287 and later (its function-hooks plugin API is early access); otherwise a terminal split, a browser view whose content security policy blocks all external requests, or an HTML export.

Council

/pulsar:council asks your other connected models the same question and shows the answers side by side. The card is illustrative.

Observatory

pulsarcode top: live sessions, tokens per second, time to first token, relays and circuit breakers. The card shows demo data.

Pilot · opt-in · off by default

Computer use you can see coming

With pulsarcode pilot on the model can take screenshots, move the pointer and type. The pulsar cursor shows where it is about to act.

  • You arm it in your own terminal; pulsarcode pilot on refuses inside a Claude Code session.
  • Actions are not pre-approved: Claude Code's permission system decides, and in its default mode it asks you each time.
  • A session with Pilot armed never relays: screenshots go only to the model you chose.
  • Failsafe corner (top-left), a limit of 10 actions per second, and a local audit log with no typed text and no images.
  • Input is refused when the window in front changed since the last screenshot (where the system can tell), and shortcuts that log out, lock, force-quit or power off are never pressed.

Privacy and security

Local by design, token-gated by default

What leaves your machine in the default configuration, and how the local router is kept to itself.

Where your data goes with Pulsar Code
WhatWhere it goes
Your prompts, code and tool resultsTo the provider and model you picked. If that provider fails before the first byte of an answer, the same request goes to your relay chain (pulsarcode relay off turns that off). Automatic relay stays among the listed hosted providers: a local server or a custom URL never relays on its own, and a session with Pilot armed never relays. When you use Council, the question also goes to your other connected models; Claude Code asks first unless you typed /pulsar:council yourself.
Your API keysOnly to the provider each key was matched to. Stored in ~/.pulsarcode/keys.json (0600, directory 0700, atomic writes). Upstream redirects are not followed, so a key cannot be bounced to another host, and a key is never sent over plain http to a host outside your machine and local network unless you set PULSAR_ALLOW_HTTP=1.
What Claude Code seesOn the default route, a random local session token, not your provider key; provider keys exported in your shell are removed from its environment. Deny rules keep its Read and Edit tools away from Pulsar's keys, the tokens in Pulsar's run/ folder, the logs and the isolated profile's credentials, and its Edit tool away from what Pulsar runs, on Windows too. The cloud routes (Bedrock, Vertex AI) hand Claude Code that cloud's own credentials.
Upstream textErrors, notices, diagnostics and council answers are scrubbed of your key, Bearer values and known key shapes before they reach Claude Code, the event bus or the next provider in a relay chain. Successful model output is passed through as is.
The local routerPulsar Core binds 127.0.0.1, checks the Host header against DNS rebinding, refuses foreign browser origins, caps request bodies and wants a token on each API call (health probes aside). The browser Stage view gets a derived, read-only token.
The folder you work inPulsar does not import Python code from your working directory, so a repository that ships its own pulsar package cannot run code through Pulsar.
PilotOff by default. Actions are not pre-approved: Claude Code's permission system decides, and in the default mode it asks you each time. Failsafe corner, rate limit, and an audit log without typed text or images.
TelemetryNone from Pulsar: there is no Pulsar server, account or analytics. Claude Code's telemetry, error reporting, non-essential traffic and auto-update are switched off for Pulsar sessions.

FAQ

Questions, answered plainly

Do I need Pulsar Code, or just ANTHROPIC_BASE_URL?

If one provider with a native Anthropic endpoint is all you need, set ANTHROPIC_BASE_URL and you may not need Pulsar. Recent Ollama versions and OpenRouter can talk to Claude Code directly, and DeepSeek, Kimi, GLM and MiniMax publish Anthropic-compatible endpoints. That is a fine setup.

Pulsar Code earns its place when your provider speaks only the OpenAI wire, when you use more than one provider, when you run open models whose tool calls need repair, when you want compaction to follow the model's real window, when you want your upstream key out of Claude Code's environment, or when you want Stage, Council, Pilot and the Observatory.

What it costs you: one more local process; a translation layer that can lag behind a new Claude Code field; and a configuration Anthropic does not support. Claude Code is built and tuned for Claude models, and results with other models vary.

Does Anthropic support or endorse this?

No. Pulsar Code is an independent project, not affiliated with or endorsed by Anthropic. Anthropic does not support routing Claude Code to non-Claude models, so a Claude Code update can change behavior. Please report problems to Pulsar Code, not to Anthropic.

Pulsar uses Claude Code's documented configuration (the LLM gateway settings, per-session settings and plugins). Pulsar Code v3.0.0 is tested with Claude Code 2.1.287 through 2.1.296.

Is Claude Code modified?

No. Pulsar Code launches the official Claude Code CLI you installed, unmodified, and configures it through environment variables, a settings file and a plugin directory for that session. It does not patch, bundle or redistribute Claude Code. Run claude directly any time and it is untouched.

Do my own skills, hooks, MCP servers and plugins come along?

Your project's do: the .claude/ folder and .mcp.json in the folder you work in are read as usual. Your user-level setup in ~/.claude does not by default, because Pulsar Code launches Claude Code with a profile of its own and leaves ~/.claude alone. PULSAR_SKILLS=skill-a,skill-b copies those skill folders from ~/.claude/skills into that profile at each launch. Or set PULSAR_CLAUDE_CONFIG=shared to use your own ~/.claude as it is (Pulsar then leaves CLAUDE_CONFIG_DIR as you set it).

Which providers can I use?

36 provider profiles in v3.0.0, plus any OpenAI-compatible URL, or an Anthropic Messages URL ending in /anthropic:

  • Keyed adapters 22: NVIDIA NIM, OpenRouter, OpenAI, Google Gemini, Groq, xAI, Mistral, Cerebras, Together AI, Fireworks AI, Hugging Face, DeepInfra, SambaNova, Vercel AI Gateway, Requesty, Novita AI, Alibaba Qwen, Nebius Token Factory, Venice, Chutes, Cohere, Azure OpenAI
  • Native Anthropic Messages 6: Anthropic, DeepSeek, Moonshot Kimi, Z.ai GLM, MiniMax, Azure AI Foundry (Claude)
  • Clouds 2: Amazon Bedrock, Google Vertex AI
  • On your machine 6: Ollama, LM Studio, llama.cpp, vLLM, Jan, LocalAI
Which model should I start with?

Models with strong tool calling do best in Claude Code's agent loop. The picker ranks each connected catalog and suggests a tier, but the honest answer is to try two or three on your own work: switching is one command, and the Observatory shows how each one behaves.

Does it work offline with local models?

Yes. Ollama, LM Studio, llama.cpp, vLLM, Jan and LocalAI servers on your machine are found on loopback, and the key prompt offers one it finds; or type ollama at the key prompt or paste a local URL. Local servers skip your HTTP proxy by default (PULSAR_PROXY_LOCAL=1 overrides that). For a server you host elsewhere, set PULSARCODE_LOCAL_ENDPOINT to its OpenAI-compatible URL (or an Anthropic Messages URL ending in /anthropic): Pulsar adds it as a profile and prefers it at launch while it answers.

Where do my keys go?

Into ~/.pulsarcode/keys.json on your machine, and from there to the provider each key was recognised for, by Pulsar Core on loopback. Never type a key as a command argument: pulsarcode key reads it at a masked prompt, or use --stdin or --from-env VAR.

How are updates handled?

pulsarcode update installs the latest release tag, checked against its SHA256SUMS (pulsarcode update v3.0.0 pins one). It never installs a tag older than v3.0.0, never moves to an older version than the one running unless you add --allow-downgrade, and stops with a clear message when the latest release cannot be found; pulsarcode update main installs main when you ask for it. Pulsar sessions switch off Claude Code's auto-updater (PULSAR_CLAUDE_AUTOUPDATE=1 turns it back on); Pulsar runs the same claude binary you use directly.

What does it cost?

Pulsar Code is free software under the AGPL-3.0-or-later. Model usage is between you and your providers: several have free tiers, and local models run on your own hardware.

What do I need installed, and how do I remove it?

macOS, Linux, WSL or Windows (native Windows is experimental; WSL gives the smoothest ride). On macOS, Linux and WSL the installer needs bash, tar and curl (or wget); on Windows, PowerShell. pulsarcode uninstall removes Pulsar Code and leaves Claude Code installed.
