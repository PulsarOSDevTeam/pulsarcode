# Brand assets ("Observatory")

Everything under `assets/brand/`, `assets/readme/` and `docs/assets/brand/` is generated by the
scripts in this folder. Never edit the outputs by hand: change the generator, regenerate, review the
frames, and bump the version suffix (`.v3` -> `.v4`) in `hero.py` on any visual change, so GitHub's
image proxy cannot serve a stale copy.

## Regenerate

```sh
python tools/brand/make_assets.py            # everything, then check.py (PNGs need Playwright + Chromium)
python tools/brand/make_assets.py --no-png   # vector assets only, no browser
python tools/brand/make_assets.py --mp4      # also an MP4 clip into $PULSAR_LAUNCH_DIR (never committed)
python tools/brand/check.py assets docs/assets/brand README.md
```

Outputs are deterministic: the same code produces byte-identical SVGs (seeded starfields and noise).
`tests/test_brand_assets.py` fails when a committed SVG is stale.

| Script | Writes |
|---|---|
| `motion.py` | `tokens.json`: the clock (`P1`, `P2` from `pulsar.fx.Beams.angles`), easings, springs, palette, pixel font, tagline, computed provider groups and the hero readout |
| `hero.py` | `hero-{dark,light}.v3.svg`, `hero-static-{dark,light}.v3.svg`, `docs/assets/brand/hero-inline-dark.svg` |
| `readme_art.py` | dividers 1-4, Signal Path, four feature cards, provider constellation, footer (each in dark, light and `-static`); `--providers-md` prints the "All providers" table |
| `mark.py` | `mark.svg`, `favicon.svg`, `favicon-16.png`, `favicon-32.png`, `apple-touch-icon.png`, `avatar-512.png`, `logo.svg`, `logo-light.svg` |
| `capture.py` | frame-exact captures, contact sheets, `social.png`, the PNG stills of the posters (`--stills`), the optional MP4, the hero acceptance checks |
| `check.py` | the validator (also run by `tools/demo` on `assets/demo/`) |
| `make_assets.py` | runs all of the above, copies the site files and writes `docs/assets/brand/providers.json` |

## Capture and review

`capture.py` loads an SVG as the page, pauses every animation (`document.getAnimations()`) and sets
`currentTime`, so a frame is the exact state at T ms.

```sh
python tools/brand/capture.py assets/brand/hero-dark.v3.svg --at 0,333,600,750,1650 --pulse --out /tmp/h/d
python tools/brand/capture.py assets/brand/hero-dark.v3.svg --sheet 12 --out /tmp/h/sheet.png
python tools/brand/capture.py assets/brand/hero-light.v3.svg --reduced --out /tmp/h/rm
python tools/brand/capture.py --accept --out /tmp/h/accept    # hero checks A1, A3, A4, A6, A8, A9 (capture.accept)
```

## Embedding

Every animated README image ships a static poster and is embedded with the 6-source `<picture>`
(narrow screens first, then reduced motion, then colour scheme). The poster is there because an SVG
inside `<img>` does not see the page's reduced-motion emulation. Each SVG also carries its own
`prefers-reduced-motion` block as the last rule. Names come from one rule, `svgkit.themed_name()`:
animated `<stem>-<theme>.v3.svg`, poster `<stem>-<theme>-static.v3.svg`, with the hero as the single
exception (`hero-static-<theme>.v3.svg`, its original name, which the Pages build relies on). The
generators, `check.py` (which also fails on an animated themed SVG missing a poster or a still) and
`svgkit.picture()` all use it. `picture()` emits the markup, for example:

```html
<picture>
  <source media="(max-width: 767px) and (prefers-color-scheme: dark)" srcset="assets/brand/hero-dark-still-v3.png">
  <source media="(max-width: 767px)" srcset="assets/brand/hero-light-still-v3.png">
  <source media="(prefers-reduced-motion: reduce) and (prefers-color-scheme: dark)" srcset="assets/brand/hero-static-dark.v3.svg">
  <source media="(prefers-reduced-motion: reduce)" srcset="assets/brand/hero-static-light.v3.svg">
  <source media="(prefers-color-scheme: dark)" srcset="assets/brand/hero-dark.v3.svg">
  <img src="assets/brand/hero-light.v3.svg" width="100%" alt="...">
</picture>
```

**PNG stills for narrow screens.** In October 2026 GitHub's phone app drew the PNG files of a private
repository's README and left every SVG file of the repository as a broken image. So each poster also
ships as a PNG still, `<stem>-<theme>-still-v3.png` (`svgkit.still_name()`, no dot before the extension),
and the two narrow sources come first: a screen under 768 px never selects an SVG, and shows the
artwork without motion. `capture.py --stills` renders them from the posters (Chromium, transparent
background, 1280 px across, the 600-wide cards doubled) with the site's two faces embedded, so a still
does not depend on the fonts of the machine that renders it. The terminal replay does the same with
its poster from `tools/demo/posters.py`.

To verify on GitHub, push a test branch and open its README, on a wide screen and in the phone app:
the combined-media `<source>` must survive the sanitizer, the animations must play on the wide
screen, every image must show on the phone, and the light theme must show the chart-recorder
plate. If the combined media query is stripped, fall back to the
two-source `<picture>` (colour scheme only) and rely on the in-SVG reduced-motion block.

## Site copies (`docs/assets/brand/`)

- `hero-inline-dark.svg`: paste between `<!-- hero:begin -->` and `<!-- hero:end -->` in
  `docs/index.html`. Every id, class and keyframe name is prefixed `h-` and there is no XML prolog,
  so the inline copy cannot collide with page styles.
- `constellation-site.svg`: same layout as the README constellation, no animation; ids and classes are
  prefixed `c-`, the beam is `g.c-beam` (rotate it from `data-angle` values), each node is
  `g.c-node[data-id][data-angle]` (screen degrees, clockwise from +x, y down).
- `providers.json`: `count`, `prefixes` (`[prefix, id, name, route, wire]`, longest first, from
  `pulsar.providers._BY_PREFIX`), `unlisted` (prefixes of profiles Pulsar Code recognises but does not
  list; check them before shorter prefixes), `reject` (`[prefix, first sentence of the note]`),
  `ambiguous`, `groups` and `names`. No keys, no URLs.
- `tokens.json`: the motion and colour tokens.

## Rules the validator enforces

No script, event handlers, `foreignObject`, `@import` or external references; no em dashes; no
"free Claude Code" or "Claude Code x" lockups; no key-shaped strings other than
`sk-or-v1-fake-key-not-real`; every "N providers" equals `len(advertised_providers())`; size budgets
in `check.py`; no animation in `-static` files; a reduced-motion block (with
`*{animation:none!important}` first) as the last rule of every animated SVG; hero cells animate with
`forwards` only.

## Design notes (and why)

Stage names follow `hero.py`: S1 ignition, S2 strike, S3 glint, S4 pulse, S5 decode. The A checks are
`capture.py --accept` (see `capture.accept`).

- **S2 kick is rigid per letter.** Every cell is still struck (white-hot or wet-ink flash) at its own
  shockwave arrival, but the 7 px kick moves each letter (`g.lt`) as one body, from the instant the front
  first touches that letter, along the vector from the core to the letter's centroid. Per-cell kicks
  struck about 5 ms apart drifted 1 to 3 px apart in the E_SETTLE phase and opened seams that the
  0.9 px overlap could not hide. The kick ends at `translate: 0 0`, so it has no fill mode.
- **S2 `hit` keys on the dark plate.** Light keeps `6% HOT, 35% WARM` (wet ink drying).
  Dark holds HOT for the 2-frame impact and reaches WARM by 110 ms (`5.376%`, `17.742%`): with 6 / 35 the
  near-core cells are still WARM (near white) at 600 ms, so acceptance check A3 (a hot-to-colour
  gradient at 600 ms) cannot hold. `hero.HIT_KEYS` holds both.
- **S2 strike in strips.** The animated heroes strike each cell in `hero.HIT_STRIPS` (3) vertical
  strips, each at its own shockwave arrival. Neighbouring 15 px columns cool about 7 ms apart and
  E_COOL's steep start turned that into visible per-column bands at 600 ms; 5 px strips make the
  hot-to-colour front a soft wipe. Posters keep one rect per cell.
- **The hero paper starts blank.** The pen inks from `hero.PEN_DOWN` (clock origin + 0.6 s, between two
  pulses) and the recording grows leftwards from the pen: one mask rect slides at paper speed until the
  ink reaches the left edge (about 37 s). That is one extra running animation during those 37 s; the
  steady state is unchanged.
- **Footer decay is baked into the paper.** A chart recorder cannot shrink what it already wrote: the
  strip carries full-height history left of the pen, the geometric decay (ratio .55 per half turn,
  `readme_art.footer_amp()`) over the 2*P1 of paper right of the pen, then a flat line, and it scrolls
  past the fixed pen. The 4*P1 seam is a 300 ms cross-fade between two copies of the strip (the
  incoming one already moving at paper speed); left of the decay the copies are identical because the
  loop is exactly four paper periods.
- **Signal Path tokens** are spaced so the stream fills 3.0 to 7.8 s (`readme_art.STREAM`, about 210 ms
  apart at 240 px/s) instead of 90 ms apart, which ended the stream at 5.8 s and left a third of the
  loop static. Every dynamic element sits in an `.xf` group and they all dissolve in one 450 ms E_SETTLE
  fade from 9.6 s; the schematic and the timeline axis and labels never fade.
- **Stage flip.** The old slide folds edge-on (scaleX 1 -> 0, 180 ms, E_CHARGE: a card turning away
  accelerates), the page counter changes at the swap, the new slide unfolds with E_SPRING. The card
  opens 0.6 s into its loop (`STAGE_LEAD`) so frame 0 shows the pane docked, and the pane leaves and
  re-docks within 250 ms around the seam.
- **Pilot `key` has no chip.** `pulsar/pilot/overlay.py` clears the chip on a key op and draws keycaps
  plus a pulse ring at the cursor, so the card does exactly that (and the mock app's title bar answers
  ctrl+s with "saved"). The `type` op fills the field with one bullet per keystroke over the overlay's
  own duration (`chars * 0.012 + 0.4` s); the text itself is never shown.
- **Observatory** shows the PROVIDERS panel: breakers are per target (`profile|model`), an open
  breaker drops that target's throughput to 0 and a feed line names the relay. Provider names are ink
  with a route-coloured dot; red-family text is reserved for status.
- **Constellation orbit names** sit on their orbits along one spoke (a scale, LOCAL to ADAPTERS), each
  knocking its dashed line out; node labels keep `RING_PAD` away from them. The centre reads
  `36` / `provider profiles`, the README's wording (`motion.count_phrase()` is "N provider profiles in vX").
- **S1 impact flash is local.** A full-bleed flash rect (ICE .24 / PLASMA-ink .10) washed the
  whole frame grey (dark) or lilac (light) at 300-400 ms and greyed the ghost letters; the rule is no
  letter wash above .10 and no full flood. The flash is now a radial lift centred on the core
  (`hero.IGN_R` 720 px; peak is the theme's `flash_op`, about .28 of it by the first letter and 0 at
  the rim) plus a core bloom of `hero.IGN_BLOOM` 190 px that stops before the wordmark. Timing, shake
  and shockwaves are unchanged.
- **Hero readout, keyless entry** shows `ollama`, the word the CLI's `detect()` maps to Ollama, not
  `localhost` (which `detect()` does not accept).
- **social.png** is reduced with a 4x4 ordered (Bayer) posterize instead of a dithered palette (no
  error diffusion, no speckle), captured in software raster on one thread, and an existing file is kept
  when a new render differs only by raster noise (`capture.same_picture`), so make_assets does not
  dirty git. The social glint prints at full strength (`Layout.glint_op`), being a single still. Its
  footer still says "N providers" (`hero.SOCIAL_UNIT`): `tests/test_screens_public.py`, outside
  tools/brand, pins that word on the social card.
- **Observatory sparkline** scrolls (one period of data per 4*P1) with a pen dot at the right edge,
  instead of redrawing with `stroke-dashoffset` (a dashboard should never blank).
- **Pilot comet** is the overlay's own tapered ribbon (`overlay._trail`: last 100 ms of the path,
  half-width `(0.3 + 8.5 f^1.8) k`, ink outline) instead of 6 discrete copies, which read as dots at
  glide speed.
